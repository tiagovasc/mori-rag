# Architecture

1. Validate explicit original units and complete summaries. Reject missing fields, conflicting IDs and changed model fingerprints.
2. Split originals into readable parent passages with exact start/end offsets: by default, target 400 words with sentence/paragraph boundaries and roughly 50 words of overlap. Long sentences fall back to word boundaries; the optional `words` strategy uses whitespace windows. Embed token-bounded child spans without truncating parent text, and embed complete summary coverage as segments. Rank a parent by its best child cosine match. Commit the complete import transaction only after every embedding succeeds.
3. Preflight the maximum rating decision count and any required answer/rerank provider. Prompt extension is off by default. When enabled, one source-free LLM call adds up to four retrieval variants to the original question; generation or additional-query embedding failures fall back to the original with a notice. Embed with the configured query prefix and interleave exact-cosine rankings within one shared candidate cap. Deduplicate whitespace-normalized exact text within each unit, continuing down the ranking to fill the cap. Identical words from different units retain their distinct identity and context. Generated variants never become evidence; Jev and the final answer use the original question.
4. Jev rates each passage against the original question. Optional same-unit neighbors affect rating context only when enabled. Independently rate complete summaries, optionally after semantic summary preselection. When both `full_units` and `summaries` are zero, skip summary selection, rating and its call budget entirely.
5. Select full units from the summary ranking and exclude their IDs from other summary selections. Optionally exclude their passages before filling the Jev shortlist; this backfills from the ranked candidate pool rather than returning duplicate evidence.
6. In default fixed mode, take up to 20 final passages, or ask the optional LLM to order every shortlist ID exactly once and retain its top `rerank_k`. In context mode, keep the ordered shortlist as the candidate pool and ignore fixed final caps. Missing, duplicated or invented rerank IDs fail explicitly.
7. Assemble full originals, separately labelled summaries and exact original parent passages. Carry stable unit IDs and source metadata into both readable context and the model handoff, including authorship, URLs and extraction caveats. Add answer-stage neighbors independently from rating neighbors. Context mode first requires complete selected units and summaries to fit, then adds whole passages in order, skipping those that exceed the remaining allowance. It measures the complete answer prompt at one estimated token per UTF-8 byte, reserves output and adapter overhead, and enforces both character guards. This conservative estimate is not a model-specific token count. Fixed mode checks the rendered context character guard; the LLM adapter also checks its input character guard. Neither mode silently truncates originals.
8. Save the portable context and exact answer prompt. Optionally call the configured answer provider. Validate supplied citation IDs and require citations on substantive paragraphs before publishing an answer.

## Failure and preservation

Corpus imports use a transaction; failed imports publish no partial new units. Queries preserve requests and retrieved inputs even when later stages fail. Jev caches every successful decision as it finishes, making explicit retry inexpensive. There is no silent cosine fallback when Jev fails and no automatic restart of interrupted model generation.

Run artifacts remain in the configured data directory: requests, extension status/variants, retrieved inputs, ratings, context, prompt and available answer/failure artifacts. Rejected model answers are retained separately from validated answers. These records may contain source text and questions; the reference implementation provides no automatic expiry policy. Keep data directories private and apply your own retention policy.

A source can contain many units. Each stored unit ID is immutable: its hash binds the title, source identity, original, summary and metadata. Identical reimports avoid embedding calls. Model fingerprints include provider, requested model/revision, endpoint when relevant, task prefixes, chunk policy, normalization and vector dimensions. Use pinned model revisions for reproducibility; a mutable server-side alias can still change despite a stable requested name. The current reference implementation does not hash every model weight on every startup.

When `--summarize` reimports an unchanged unit, its persisted summary and generated provenance are reused without another model call. Source-field changes still require a new version. Every summary-segment vector is validated and normalized; segments use the configured embedding batch size, and current retrieval uses the best matching child rather than a mean-vector ranking. Legacy fingerprints that omit a requested dimension are treated as the equivalent default of zero; switching between an explicit dimension request and the provider default is rejected.

## Local interface

The local server serves one page and a small JSON API. Progress snapshots stay source-free. While a query runs, an in-memory board (`mori/live.py`) records each candidate's rating level, the rating counts and the strongest passages with short excerpts; `/api/live` serves it to the progress screen, and it is never written to disk. Stop sets a cancellation flag that the pipeline checks between stages and after each rating; the run is saved as `stopped` and completed ratings remain cached. The reader asks the store for one unit's text and passage offsets (`/api/unit`). Citation verdicts are written to `verdicts/<run id>.json` in the data directory, outside the run folders, which stay unchanged.

## Reference implementation and scale

Python owns orchestration; providers are small independent adapters. SQLite stores units, exact chunk text, normalized vectors and decision cache. Exact cosine scoring is dependency-free but scans the collection; it is not an ANN index. Threaded relevance calls have configurable bounded concurrency. The local server admits one import/query job at a time; CLI callers should avoid concurrent writes to one data directory.

Embeddings and Jev have independent provider/model settings. Summary generation, reranking and answering share `llm_model`; only prompt extension can use `query_expansion_model` through that same LLM adapter. The local interface permits model choices from the configured default and `llm_models` allowlist. Model selection does not automatically change context limits or the server-controlled counting policy.

Provider calls have bounded input bytes, timeouts and retries. The preflight distinguishes decisions from possible HTTP attempts: retries can multiply actual calls and billing. API model aliases and remote behavior are outside local reproducibility guarantees. Cached requests use the requested model; use explicit versions or a fresh corpus/cache directory to force a new evaluation after a provider change.

Use the database/export and provider contracts in [ADAPTERS.md](ADAPTERS.md). Do not imply that changing a database URL alone changes the reference SQLite implementation into a scalable multi-tenant service.
